# API route conventions

- `-lib/contract.server.ts` composes the resource groups into the executable Effect HttpApi and OpenAPI source. Shared schemas and middleware context live in `shared.server.ts`. Keep route names, operation IDs, wire fields, status codes, and error semantics stable. Regenerate `webapp/public/api/openapi.json` after changes.
- Keep public schemas separate from Drizzle modules (`src/api/management.ts`). Explicitly select public and mutable fields, use snake_case on the wire, camelCase in handlers, and preserve customer metadata keys. Apply write limits to inputs, not existing records in responses. Document creation defaults and actual framework error behavior.
- Keep resource queries in `src/db/tenant.server.ts` and `src/db/tenant-user.server.ts`. Derive organization and Tenant scope from verified credentials and include it in every predicate. Never trust scope from request data.
- Colocate each resource's schemas, endpoint group, and handler factory in `-lib/<resource>.server.ts`. Pass the composed API into the factory and defer repository/pagination imports until layer construction, keeping OpenAPI generation database-independent without runtime import cycles.
- Declare OpenAPI security on endpoints with `OpenApi.Override` or the group's `annotateEndpoints`. Never infer credential requirements from display tags or operation names.
- Use plural nested routes for TenantUsers and internal UUID path IDs. Validate with Effect's UUID builtin and publish `format: uuid` without a regex. Database-generated IDs remain UUIDv7. Do not add lookup routes, deletes, sorting, counts, or unsupported filters without an API decision.
- Listing uses lazy keyset pages from `src/db/lib/pagination.server.ts`. Preserve deterministic indexed ordering, directional cursors, filter binding, and live-listing semantics. Every emitted cursor must fit the accepted input limit, including maximum-length Unicode identities and filters.
- List responses use nullable `page_after` and `page_before` continuation values, passed as the same-named request parameters. Null means no page in that direction, not an echoed request boundary.
- Keep authentication, cursor signing, error conversion, CORS, and cache headers in REST transport. Keep stored TenantUser admin separate from signed JWT authority.
- Organization JWTs must resolve the email to an existing `user` joined to `member` in the claimed organization on every request and carry the matched user and database role as `restScope.currentUser`. Apply the shared `tenantManagement` role policy (owners/developers read and write, viewers read only), never token role claims. Match the dashboard's membership ordering and never create identities or login sessions during this check.
- Keep RFC 9457 `AstralBeamApiError`, safe setup failures, and no-store/CORS behavior consistent across success and error responses.
- The v1 catch-all owns preflight, setup, CORS, cache headers, and HTTP errors for every group. Resource authorization stays on Tenant groups. Chat uses tenant JWTs for run/config and signed tickets for downloads, preserves AG-UI camelCase and SSE through `handleRaw`/`fromWeb`, and keeps its bounded body reader and separate rate bucket.
- Temporary `/api/chat` aliases rewrite only the request path and call the same `-lib/route.server.ts` entrypoint. Keep them out of OpenAPI.
- Convert typed domain failures at the handler boundary without `orDie`. Log unexpected failures once with safe diagnostics, including failures during setup and dispatcher initialization.
- Add durable behavior tests through the actual Effect handler, prefer `HttpApiTest` when setup remains small, and avoid tests that only duplicate schema or generated-output details. Prefer one test file per server module. Keep cross-resource HTTP flows together in `transport.test.ts` rather than duplicating fixtures across resource tests.
- Consumer guides belong under `src/routes/docs/-content/api` and are included in the generated specification. Keep them SDK-agnostic and put endpoint details in the executable contract.
- Generate the single canonical `/api/openapi.json` asset before builds. Scalar fetches that asset and groups shared errors only for presentation. Downloads retain explicit statuses. Keep one OpenAPI URL, cache revalidation and CORS. Scalar examples must omit unset optional parameters without hiding their documentation or weakening API validation.
