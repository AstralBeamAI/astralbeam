# SDK development

- Limit comments to two lines max. Don't state what's obvious from the code, just brief reasoning.
- Read [ARCHITECTURE.md](./ARCHITECTURE.md) before touching entry points, the chat widget, or the build, and update it in the same commit whenever that structure changes.
- Explain structural and build decisions in `ARCHITECTURE.md` rather than in long code comments; keep an inline comment to what is specific to that line.
- `tsdown` is pinned to exactly `0.22.3`: newer versions pull in `rolldown-plugin-dts@^0.27`, whose `yuku` native bindings fail to load under Deno because module load hooks compile `.node` addons as JavaScript ([denoland/deno#36240](https://github.com/denoland/deno/issues/36240)). Re-test the pin once that issue is fixed.
- Each file in `src/` named in `tsdown.config.ts` is a public entry point and maps 1:1 to the `exports` field in `package.json`; add new entry points in both places.
- `react`, `react-dom`, and `vue` are optional peer dependencies; keep framework imports confined to their respective entry points so consumers of the other entry points never load them.
- Never export the chat widget under `src/chat/` or reach it by any route other than the dynamic import in `src/client.ts`, so it stays inside the client pass's lazy chunk with its own bundled React.
- Everything the chat widget imports must be a devDependency so tsdown inlines it into the chat chunk; adding it to `dependencies` would force hosts to install it.
- Generate shadcn components with `deno task ui add <component>`; never edit `src/components/ui` beyond minimal typed fixups. `components.json` stays on the plain `b0` preset baseline (`base-nova` style, `neutral` base color, RTL) with the phosphor icon library — intentionally independent of the webapp's `base-lyra`/`mist` styling.
- Hand-written chat components live one per file directly in `src/components` (shadcn keeps `src/components/ui`). `src/lib` splits along the lazy-chunk boundary: `client-types.ts`, `client-constants.ts`, and `client-utils.ts` hold what the eager client entry loads (public API types, defaults, the debug-line logger) and must not import chat-chunk modules, while `types.ts`, `constants.ts`, `utils.ts` (shared helpers, including shadcn's `cn`), and `debug.ts` (stream-chunk logging) belong to the lazy chat chunk.
- `src/chat/styles.generated.ts` is gitignored, never edited by hand, and regenerated by `deno task generate:styles` (run first by both `build` and `check`); a fresh checkout needs one of those before a standalone `typecheck` or `knip` can resolve it.
- Keep `examples/*` standalone consumer apps on the built `dist` via their `file:../..` dependency, with no Tailwind or shadcn of their own, so they keep demonstrating the shadow-root style boundary.
- Publish with `deno task build` followed by `npm publish` from `sdk`; the package ships only `dist`, `README.md`, `LICENSE`, and `package.json`.
