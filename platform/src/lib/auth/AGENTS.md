# Authentication

- Preserve verified email/password and Google/GitHub sign-in. Do not enable other sign-in methods, implicit OAuth signup, change-email, account deletion, Better Auth organization deletion, teams or dynamic roles without product scope. Keep encrypted OAuth tokens, verified-email linking, final-method protection, database rate limits and fresh-session checks. Leave session cookie caching disabled.
- Keep static Organization roles composable, default invitations to viewer, and invite/edit controls single-select. Viewer/developer roles share Better Auth member access.
- Keep legal acceptance explicit and server-owned only when policy URLs exist. Require both Turnstile keys and let Better Auth/UI own tokens and resets. Keep `tanstackStartCookies()` last and configure only product-specific overrides.
- Owners/developers manage API keys and viewers must neither fetch nor render them. Preserve UUID-owned `abo_` credentials, trimmed names and server-only signing digests. Never enable API-key login sessions. Organization management uses database membership/roles, never Tenant-admin authority or token role claims. Call organization-management UI “Members”.
- Keep API-key deletion under `ApiKeys.remove` row locks, protecting the last key and `dogfood_api_key` by UUID. Authorize before disclosing protections and rate-limit dashboard token issuance before signing. Dashboard directories use organization-management tokens, never dogfood tokens.
- Keep blocking authentication sends behind `deliverBlockingAuthEmail`, with `advanced.backgroundTasks` unset and request-scoped failure propagation. Delivery failures return safe `503 EMAIL_DELIVERY_FAILED`, never provider messages. Only the shared Mailer logs outcomes, with codes and masked recipients, never message bodies or token URLs.
- Welcome and password-change notices stay asynchronous so delivery failures cannot reverse successful authentication. Welcome credential accounts after verification and OAuth accounts after verified creation, once each.
- Preserve partial-completion recovery: signup leaves unverified rows, duplicate signup resends verification or an account-exists notice, reset retries mint tokens, and invitation failures refetch the pending invitation. `/send-verification-email` returns the same generic success without sending mail for unknown and already-verified addresses. Unverified sign-in does not send email automatically.
- Preserve symmetric signup sends during outages. Give `/sign-up/email`, `/request-password-reset`, `/send-verification-email`, and `/organization/invite-member` separate `customRules` rate-limit buckets in addition to applicable Turnstile checks. Apply the same protection to new unauthenticated email paths. Password-reset failures revealing registration during provider outages are an accepted tradeoff. Retrying signup retains the original password, so a different password requires reset.
- Keep password-reset wrappers request-scoped and delegate input validation, errors and password updates to the original endpoint/plugins. Preserve rejected links and atomic single-use consumption. Until [Better Auth #10632](https://github.com/better-auth/better-auth/issues/10632) is fixed, check token expiry and the cached original password hash before original consumption. After [the ordering fix](https://github.com/better-auth/better-auth/pull/10717), remove the wrapper and `Clock` import, then verify retries/single use. Keep `/reset-password` in `haveIBeenPwned.paths`.
- Saving `/configure` settings must not provision an owner or send email. Explicit dogfood invitations reuse pending resources, keep recipients editable until delivery succeeds, transfer only membership on replacement, and retain Organization/credential identity. Lock Organization fields after creation and display current persisted values by UUID. Better Auth owns reset tokens and credential creation, without the Admin plugin.
