# Public API

- Keep the executable Effect HttpApi contract authoritative and public REST schemas independent of Drizzle. Preserve names, statuses, errors and wire fields. Regenerate OpenAPI after changes. Resource fields use snake_case on the wire and camelCase internally, preserving customer metadata. Chat retains AG-UI camelCase/SSE.
- Use typed public/mutable projections. Bound request bytes before parsing, constrain names and encoded metadata at writes, and reject PostgreSQL-unrepresentable strings including keys/filters while preserving existing-record reads. Do not add lookup routes, deletes, sorting, counts or unsupported filters without an API decision.
- Derive full Organization/Tenant scope from verified credentials and include it in every query. Organization API keys have owner-equivalent Tenant permissions within their scope, with lifecycle checks/rate limits and no user impersonation. Organization JWTs resolve current membership and database role on every request, without creating identities/sessions.
- Keep signed JWT authority separate from stored TenantUser admin. Owners/developers may manage Tenants, viewers may read. Token role claims never replace database roles. Treat `kid` as a lookup hint until ownership, signature, lifecycle, issuer and `astralbeam` audience pass verification. JWT subject remains optional.
- Keep `POST /me` JWT-only and outside resource authorization. Synchronize verified Tenant/TenantUser identity atomically, preserving omitted admin and defaulting new users false. Explicit admin changes grant no authority beyond the JWT. Organization JWTs return existing membership. Issuance, verification, chat and directory reads never provision or update Tenant/TenantUser identities.
- Interactive chat requires saved threads, tenant JWTs and explicit participants independently of management authority. Administrative thread reads do not grant participation. Keep admission/tool-result validation in the chat service, require one new user message, use consistent history snapshots and select rate buckets by endpoint operation. No stateless mode.
- Preserve indexed keyset pagination, directional/filter-bound cursors, live-listing semantics and nullable `page_after`/`page_before`. Every emitted cursor must fit its input limit, including maximum Unicode identities. Path IDs accept UUIDs and OpenAPI `format: uuid`, without regexes, while generated IDs remain UUIDv7.
- Keep resource authorization separate from shared transport. The v1 catch-all owns setup, preflight, CORS, cache headers and safe RFC 9457 errors on every path. Default to no-store, allowing successful chat images and previews a short private browser cache that varies by Authorization, X-API-Key, and X-File-Preview. Declare REST errors with `Schema.TaggedError`, fixed messages and `httpApiStatus`, sharing one problem codec per status. Chat retains its bounded reader and separate rate bucket. Report unexpected failures once and return a reference, including setup/dispatcher failures.
- Keep OpenAPI generation database-independent with deferred repository imports at layer construction and the shared runtime memo map. Declare security explicitly. Preserve canonical `/api/openapi.json`, revalidation/CORS and omitted unset Scalar parameters. Temporary chat aliases only rewrite paths through the shared entrypoint and stay out of OpenAPI.
- Test durable behavior through the actual Effect handler, preferably `HttpApiTest`, with cross-resource flows in `transport.test.ts`. Keep consumer guides SDK-agnostic, included in the specification, and endpoint details in the executable contract.
