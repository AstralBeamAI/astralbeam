- Follow the [code map](src/README.md) for route/service changes, the [database guide](src/db/README.md) for database work, and the [browser guide](e2e/README.md) for e2e work.
- Read the [authentication instructions](src/lib/auth/AGENTS.md) for authentication, API-key lifecycle and dashboard credentials, including callers outside that directory, and [API instructions](src/routes/api/v1/AGENTS.md) for public APIs, repositories and OpenAPI changes.

## Server code

- Use `node:` built-ins or standard Web APIs instead of Bun APIs in Platform and the shared repository `scripts/`, except `Bun.isStandaloneExecutable` and `Bun.embeddedFiles` for standalone packaging and Bun transport wrapping in the transaction guard. Enforce ordinary API usage through Oxlint in Platform only.
- Use plain data and functions with options-object inputs, not classes or closure-based state factories, except Effect services/schemas/errors and framework-required classes. Keep function and module-constant names unique within Platform except interface-prescribed and framework exports. Pass explicit type arguments when a generic parameter appears only in the return type, avoiding tsgo's inconsistent inference from surrounding `as` casts.
- Keep new functions at cyclomatic complexity 20 or lower and never increase higher legacy functions. Decode application inputs with Effect Schema and remove redundant checks afterward, preserving security, persistence, concurrency and external-system boundaries, accepted inputs and error contracts.
- Build server logic with the existing runtime, naming Effect services `astralbeam/<module>/<Service>` and tracing methods with `Effect.fn("<Service>.<method>")`. Wrap Promise APIs once in their owning service. Use `ServerRequest` for request/response access and `tryPromiseInServerRequest` for Better Auth calls. Library callbacks use `runAppEffect`, never imports that cycle back through `runtime.server.ts`.
- Keep service errors domain-specific. Map constraints with `mapDatabaseErrors`, treat other database/decode failures as defects unless callers recover, and expose only fixed safe messages. Inspect wrapped SQL errors through Effect `Cause` utilities then standard `cause` links, never arbitrary fields or message parsing. Log unexpected failures once with safe metadata and a reference, never raw messages or values.
- Prefer Effect's scoped resources, clocks, scheduling and concurrency over custom infrastructure. Reuse database cache, idempotency and locking helpers. Keep sandbox package-facing adapters independent of Platform services. Check maintained TanStack adapters and vendor SDKs before custom provider implementations.
- Keep the Bun binary working, with version/migration commands that do not initialize the server. For dependency, build or server changes, run `bun run --cwd platform build` and `bun run --cwd platform binary:check`. Retain the Nitro idle-timeout patch until [upstream supports Bun server options](https://github.com/nitrojs/nitro/discussions/2989).
- Protect the highest wholly server-only directory in `vite.config.ts`. Use `.server.ts` elsewhere, or the server-only marker for unsuffixed entrypoints. Preserve required `migration.ts` names. Browser imports from protected modules must be type-only. Never expose server environment variables.
- Apply global framing CSP to every path, including embedded APIs, as an additional policy so route restrictions remain enforced. Cross-origin fetch permissions belong to CORS.

## Database

- Use PostgreSQL 18+ and commit schema changes with reviewed migrations.
- Use PostgreSQL `uuid` keys with database-generated `uuidv7()`, `citext` email identity, and `timestamp with time zone` without forced precision. Keep SQL identifiers lower snake case, text unconstrained, and timestamp ranges half-open. Follow PostgreSQL's [Don't Do This](https://wiki.postgresql.org/wiki/Don't_Do_This) guidance.
- Preserve separate Promise and Effect pools, shared runtime lifecycle, five-second connection timeouts, `prepare: false`, and the Promise pool error listener. Do not add extra pools, `allowExitOnIdle`, global type parsers, `postgres`/postgres-js clients or separate database signal handlers. Never initialize resources during import or shutdown. Keep Drizzle adapters module-local and CLI migrations independent of Effect.
- Transactions may perform only SQL on their current connection. Put all other network I/O outside them, including raw transactions and work through sockets, subprocesses or workers. Never bypass guards, detach work or catch a guard error and continue. Keep provisioning's advisory-lock fiber separate from its external work.
- Effect transaction configuration reads use their connection without populating the process cache. Load configuration before Promise transactions, which may reuse only committed cached values. Read settings through `Config`, preserve environment precedence, and keep domain-managed values outside its operator snapshot.
- Give each entity its own primary-key ID and separate foreign-key columns. Only the organization table may have a `slug` column. Organization-owned tables require non-null `organizationId`, scoped alternate/unique keys, and unique foreign keys for one-to-one ownership. First-party organization-owned primary keys are `(organizationId, id)`, Tenant-owned keys are `(organizationId, tenantId, id)`, and message/part keys insert `threadId` before `id`. Foreign keys preserve complete target identity. Better Auth retains adapter-compatible keys, and its `member`/`invitation` composite-reference exceptions do not waive organization scoping. Obtain architectural approval for other exceptions. Before launch, change public IDs directly and migrate stored rows without compatibility aliases.
- Preserve full immutable identity as colon-joined cache-key prefixes and scope cleanup to the same namespace.
- Use `snakeCase.table`, camelCase properties without redundant SQL-name arguments, and shared column builders. Every table has `timestamps()` and non-Drizzle updates set `updated_at`. Prefer enums for closed sets, prefixing single-table enum names with the full snake_case table name. Every JSONB column uses a synchronous `schemaJsonb` codec, with `Schema.JsonObject` for flexible metadata. Raw SQL bypasses codecs.
- Use shared optimistic-lock helpers and domain `Changed` errors where locks apply, preserving Tenant/TenantUser last-write-wins semantics. Generate internal validation with `drizzle-orm/effect-schema`. Preserve inferred table row types through database helpers instead of erasing them to `unknown` and casting them back.
- Keep encrypted values behind scoped table functions, bind ciphertext to row identity, and never fall back to plaintext, write during reads or log stored values. Keep deployment settings global and organization settings scoped.
- Never rewrite migrations others may have applied. Regenerate only unmerged, unapplied iterations unused by shared deployments, replacing SQL and snapshot together. Include required extension DDL. TypeScript migration work shares rollback only through the supplied client. Record external-work intents transactionally and perform object I/O after commit.
- Keep `deferrableForeignKey()` returning Drizzle's native builder and `UpdateDeleteAction` methods. Request deferred checks for circular/cascade dependencies when nullification would lose data, and use custom migrations for timing-only changes.
- Review every recreated foreign key for explicit `DEFERRABLE INITIALLY IMMEDIATE` or requested `DEFERRED` timing. Drizzle omits it ([#1429](https://github.com/drizzle-team/drizzle-orm/issues/1429), [proposed fix](https://github.com/drizzle-team/drizzle-orm/pull/5393)). Keep referenced keys non-deferrable, use `NO ACTION`, and verify actual SQL support after upgrades.
- Preserve targeted `SET NULL (agent_id)` and `SET NULL (default_agent_id)` without nullifying scope columns ([Drizzle #5684](https://github.com/drizzle-team/drizzle-orm/issues/5684)). Drop dependent foreign keys before replacing referenced keys, then restore full references, actions and timing. Snapshots and `check` do not verify manual clauses.
- Validate schema changes on a disposable migrated database. Key/dependency changes also require a populated upgrade and `delete-organization.integration.test.ts`, covering cascades, deferred failures, targeted nullification and commit. Use `SET CONSTRAINTS ALL DEFERRED` for parent-first deletion.
- Organization deletion revokes access and submits its workflow atomically. Extend deletion coverage and direct SQL cascades for new owned data, delete Tenants sequentially before the Organization, and recover recognized commit `SqlError` defects for retry. Do not delete TenantUsers before retained authorship. Empty-batch drains must wait for locked rows.
- Each upload attempt gets a fresh immutable file ID/key. Consumers remove references before marking files purging. Retain metadata until S3 deletion succeeds and durable workflows own retries. Files do not expire. Keep cleanup independent of consumer tables, without triggers or deletion tables. Prefer lifecycle policies over exhaustive orphan cleanup.
- Avatars belong to memberships. Keep Better Auth `user.image` and `organization.logo` null. Profile-image failures must not fail authentication. Authorize before signing downloads, preserve scoped file references, and delete stored objects before cascading metadata during application deletion. Keep stored-file helpers, response formatting and maintenance independent of avatars, logos and permissions. Keep profile operations beside auth/Organization hooks and upload callers, without a separate profile-file service.
- Keep seeding rerunnable, transactional, loopback-only and separate from reset/migration. Preserve credentials, models and assignments on reruns. Only explicit development seeding may consume `OPENAI_API_KEY`. Keep `scripts/seed/fixtures.ts` dependency-free and seed imports explicit, without runtime database/service initialization.

## Cluster runtime

- Follow the [cluster](src/lib/cluster/README.md) and [workflow](src/lib/workflows/README.md) guides. Use workflows with named activities for durable recovery and `ClusterCron` for safely repeatable maintenance. Give workflow modules camelCase named default exports matching their kebab-case filenames. Workflow names may match operation names, aliasing colliding database imports with an `Fn` suffix. Effect owns `effect_cluster_*` tables and migrations outside Drizzle. Review storage privileges when upgrading aligned Effect packages.
- Await cluster cleanup before Vite terminates any shared Nitro worker, preserve `shardLockDisableAdvisory: true`, and isolate runner failures from setup. Runner addresses are environment-only and must never advertise a wildcard. Keep Vite-only syntax out of Nitro-called functions.

## UI

- Reuse existing navbar/layout components, including fallback pages. Colocate route-only components in `-components` and server functions in `-functions`, one named export per file with matching kebab-case filenames, such as `MyComponent` in `my-component.tsx` and `updateXYZData` in `update-xyz-data.ts`. Keep helpers with their consumers and shared code at the closest common ancestor. Validate server functions through `.validator` and `Schema.toStandardSchemaV1`, without Zod. Use Effect validation issues beside accessible form fields and `LocalDateTime` for reader-local dates.
- Preserve coarse-pointer touch sizing on hybrid devices and pointer cursors in registry menus/selects. Verify coarse, hybrid and fine-pointer cases, not just viewport widths.
- Use [DocsLink](src/components/docs-link.tsx) with resolved `href` URLs for contextual application guides. Keep navbar links and links within documentation pages as standard links.
- Keep Astro limited to authorized dashboard operations. Keep declarations beside schemas/helpers in `dogfood-chat.tsx`, reuse dashboard components, and preserve chat state when closed. Dock chat without a modal backdrop from 1024px upward and use a full-width panel below it. Match the 56px dashboard header and reserve content space for the fixed launcher.
- Follow [SDK presentation contracts](../sdk/AGENTS.md#presentation-and-verification) when embedding widgets. Pass dashboard theme/title choices and hide duplicate widget headers when the dashboard supplies titles. Use `APP_NAME` and `APP_HANDLE` instead of hardcoded brand text or identifiers. Preserve the root `ThemeProvider` startup script before first paint.
- Keep `/dev` synthetic and unavailable in production. Prerendered docs must contain no user-specific data. Fetch it through authenticated `private, no-store` responses. Draft docs remain publicly fetchable repository content, never confidential material.
- For `/docs`, follow the [house voice](https://swiftace.org): open with the subject and action, use "let's" and "we" for procedures and "you" for reader state, explain a command's purpose and reason before it, number steps, label asides `**NOTE**:` or `**TIP**:`, and reserve tables for reference data.

## Theme and brand

- Keep the theme compiler under `scripts/theme` pure and outside runtime imports. `brand.json` owns Platform colors. Keep hand-authored Platform CSS theme-agnostic and synchronize compiler schemas with `theme.schema.json`.
- After theme changes run `bun run --cwd platform generate:theme` and refresh email sRGB values from its output. After SVG master changes run `bun run --cwd platform generate:png`. Keep logo masters and variants under `platform/public`.

## Configuration and integrations

- Keep Platform environment files under `platform` and runtime settings in database config at `/configure`.
- On macOS use Compose for PostgreSQL/PgBouncer/Valkey/Mailpit and native RustFS. Never install host PostgreSQL or Valkey through setup. When an existing local PostgreSQL service is explicitly requested, use it directly without starting containers and preserve database isolation.
- Provision through existing setup tasks and installed tools, without initializer containers, following [SETUP.md](../SETUP.md). Preserve PgBouncer as the only loopback-published database endpoint and existing backend/host-port overrides. Direct `docker compose exec postgres` is for explicit administration. Only Codex Cloud Ubuntu uses `INSTALL_EXTRA=codex-db` with `SKIP_DOCKER_COMPOSE=true`.
- Each worktree owns a database named for its unique folder, such as `a3f4` in `.../a3f4/astralbeam`, and a bucket derived from that database. `copy-worktree-env.sh` resets only that database before setup. Keep `db-reset` free of migrations, never recreate shared volumes, and preserve configured storage on setup reruns.
- Recheck session, organization, role and scope at every server operation. Share authorization through parameterized TanStack middleware, keeping resource functions explicit where contracts differ, without a parallel Effect HTTP/RPC transport just to hide wrappers. Route/sidebar guards are navigation only.
- Resolve `$orgSlug` and membership server-side, carry permissions with loader data, and reset scoped UI only after successful organization switching. Reads never change the active organization. Components build routes from the passed slug, never refetch active organization or make UUID-based credential rendering conditional on a slug. Changing a slug breaks old URLs.
- Keep `/configure` independent of dashboard/dogfood sessions, including before limiter tables exist. Only the active encryption key authenticates operators, never database credentials. Require same-origin mutations and loopback-peer verification before trusting forwarded host/protocol. In production, require HTTPS and Secure operator cookies unless `ALLOW_INSECURE=true` is explicitly set in the environment. Reveal secrets one key at a time through authorized no-store responses. Preserve repair access and migration-based gating without a completion flag.
- Keep native S3 signed URLs and uploads working independently of optional CloudFront delivery. Use `signDownload({ objectKey, expiresAt })` with an explicit `s3` default or `cloudfront` strategy. Inactive CloudFront settings must not block S3 recovery. Accept either the assigned CloudFront hostname or an optional custom hostname.
- Storage consumers assume configured storage, without fallback provisioning. Destination changes show a non-blocking manual-migration warning and remain editable after uploads.
- Keep model providers as named organization-owned connections with scoped assignments and identity-bound credentials. Return hints only, protect assigned providers/models from deletion, preserve existing selections, and do not provision credentials for new Organizations. Their starter agent may omit a sandbox provider.
- Preserve inherited model catalog values until explicit overrides, and discard overrides when disabled. Read the encrypted global catalog uncached across replicas. Submit initial catalog download with configuration changes atomically, never from page loaders. Provider requests retain public-DNS checks and redirect refusal unless private endpoints were explicitly enabled.
- Keep decrypted provider editing responses `no-store`, without preload, cached-loader retention or stale rendering. Validate integration settings with closed provider registries and Effect schemas. Keep usage-limit rolling windows anchored to first use and invalidate counters when scope/window definitions change.
- Keep email template contracts/provenance, absolute configured URLs and synthetic previews. Retain one SMTP transport and existing security modes. Do not add provider-specific queues, retries, authentication or delivery infrastructure without product scope. Follow [provider contracts](src/lib/email/providers/AGENTS.md) when editing adapters.

## Validation

- Run integration tests only against disposable loopback databases ending in `_test`, never the development database. Test services with `@effect/vitest` and layer doubles instead of module mocks.
- Browser automation must wait for React hydration before filling sign-in fields and for Turnstile readiness before submission. Use existing page objects and `bun run --cwd platform e2e:seeded` for seeded PR evidence. Default browser suites remain free of containers and model calls.
